# App Manager - Packages, Permissions, and Profiles on Your Phone

![App Manager package details with permissions visible](https://f-droid.org/repo/io.github.muntashirakon.AppManager/en-US/icon_0Na4ecQZhaD_xCtbJ9rEhuaUfjlqhu70S_-PiBGlIes=.png)

## At a Glance

Settings can uninstall a home-screen icon and still leave you unsure of the package name, the permissions, or the tracker libraries. App Manager shows that detail and can act on it: disable, uninstall, revoke a permission, or block a component, depending on the mode and the access you have. Root or a privileged mode sees more. Without that access you still get a stronger list than the drawer, and you should not expect system apps to vanish.

- Package names and versions in one list
- Permission and component views before you tap a destructive action
- Profiles for a set you have already tested
- Backup of app data only where the mode allows it and you understand the limit
- No remote control of a phone you cannot open

A profile from the internet is someone else's phone. Import it only as a reading list. Apply one change, use the device, then apply another.

## Actions

| Action | Safer habit |
|---|---|
| View permissions | Always fine |
| Disable a user app | Easy to undo |
| Uninstall a system app | Only with a note and a way to restore the ROM |
| Revoke a permission | Check the app still does the job you wanted |
| Block trackers | Expect some apps to lose a feature |
| Batch profile | After a single-app test, not before |

1. Open App Manager and find one app by its real name.
2. Read permissions before you change them.
3. Disable rather than uninstall if you are unsure.
4. Reopen the phone's normal workflow.
5. Save a profile only of changes that survived that test.

## Fits

People cleaning and auditing their own phone. A poor fit for firmware flashing and for a locked device. A poor fit as a spyware scanner that "removes all risk." Blocking a library is not a guarantee about the rest of the app.

## Requirements

| Item | Expectation |
|---|---|
| Phone | Yours, unlocked |
| Access | More actions need more privilege; the app tells you |
| Backup | A profile is not a full data backup |
| Updates | System updates may restore packages |

## Fixes

An action is greyed out. You do not have that access. Do not follow a random root guide to force it.
The launcher crashed. Re-enable the last package.
A permission revoke broke photos. Grant it again.
A profile reapplied after an update and removed a new system piece. Review profiles after major updates.
You wanted split APKs installed. That is SAI, not this list.

## One Change Survives a Day

App Manager shows more than the app drawer. That is not a request to block every library and uninstall every system package. Open one app you recognize, read its permissions, and disable it or revoke one permission. Use the phone. If a feature you wanted died, put the permission back. Save a profile only after that day. A profile from the internet is someone else's device.

Root or a privileged mode unlocks more destructive buttons. Without it, greyed actions stay grey. Do not follow a random guide to force them. System updates restore packages. Re-read profiles after a major update before you reapply them. Split APK installs and firmware flashes are other tools.

- Package name read, not only the icon
- Disable before uninstall
- One permission revoked, then tested
- Profiles saved from your own tested list
- Grey buttons left grey
- Updates treated as a reason to review
- Backups of app data understood as incomplete for some apps

| Action | Undo |
|---|---|
| View | Nothing to undo |
| Disable | Enable |
| Revoke a permission | Grant it |
| Uninstall a system app | Often a firmware restore |

The list is an audit. The buttons are optional.
